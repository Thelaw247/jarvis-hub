# Independent reviews of v0.2.0 (2026-11-14) and the fix plan for v0.2.1

Three fresh agents that built nothing reviewed v0.2.0 (plan I02): **D** = design critique, **W** = hands-on walkthrough, **A** = accessibility (WCAG 2.2 AA). Their evidence is in /tmp/review-design, /tmp/review-walk and /tmp/review-a11y (container only). Every finding below is assigned to exactly one fix package (F1–F6). A package may only edit the files it owns; anything else goes in its report.

## F1: server and demo backend
- **W1 MUST:** the orb sticks on "waiting" forever if the approval is answered within 3 s (the script still sends `orb.state waiting`; it's held in server state, so presence never rests and a reload doesn't clear it). Make script orb steps conditional on the approval still pending; always end on `idle` after it's answered; `Hub.act` publishes `orb.state idle` after any queued step. Test it.
- **W3 MUST:** the server doesn't enforce the undo window or the approval expiry; `act("undo")`/`act("approve")` succeed after the time is up. Check against `self.now()`: reply `{ok:false, message:"The undo window has passed."}` or `"This offer ran out. Nothing was done."`; publish `approval.resolved` with status `expired` at the expiry time. Tests.
- **W4 SHOULD:** toasts and the last caption replay on every reload. Drop toasts/captions after `ts + ttl_ms` in `apply_event`; clear the caption when its approval resolves.
- **W6 SHOULD:** `move` reorders windows in server state but publishes no event. Publish a layout event (or `window.push`) so the screen and server agree.
- **W7 SHOULD (server half):** the same answer arriving twice returns an error. Make a repeat of the identical answer idempotent (`ok:true`, no second effect).
- **W13 SHOULD:** no Host check (DNS rebinding). Add `TrustedHostMiddleware` for 127.0.0.1, localhost and a configurable tailnet name; validate `set` values against the settings schema and reject anything else.
- **W-NICE:** "A study plan for this week" stays under "Ready when you are" after it's booked; remove offered items once done. Double periods in spoken/caption text ("at 4.. Source") if they come from demo data (A13).

## F2: Now view and windows
- **D1 MUST:** 7 windows on screen (Now card + 6), and the window Jarvis is talking about is placed 7th, below the fold of a scrolling canvas. The Now card counts toward the 6 (or collapses once ≥3 windows are open); the active window is always placed first; evict the oldest unpinned window; size rows to fit the viewport so the canvas never scrolls; windows `align-self:start` (no stretched blank space, D18).
- **W2 MUST:** the first click on pin/close of a non-active window does nothing (pointerdown → markActive → `active` change → header innerHTML replaced). Don't re-render the header when only `active` changes; update in place.
- **D7 SHOULD:** repetition. When a window shows an item, the Now card drops that section.
- **D5 (part):** the Now card's "One thing" flag uses accent-soft. Use the notice tokens (honey/notice-ink) plus a word; terracotta is only for the one main action and the orb.
- **W12 SHOULD:** "Bigger" turns a 1x2 window into 2x1 (shorter). Include 1x2 in the grow order, or grow width and keep height.
- **W15 SHOULD:** a pending approval stops the hub ever resting to ambient. Allow rest to ambient (ambient already shows "1 waiting for your yes").
- **A1 MUST (part):** closing a window drops focus to `<body>`. Move focus to the next window's tools (or the view heading) before removal.
- **D17 NICE:** now-awake shows one card top-left on an empty canvas. Keep the faint clock/orb or centre the card.
- **W-NICE:** in ambient mode the caption sits bottom-right instead of near the centred orb; the approval jumping to the front moves every other window at once (stagger or keep positions).

## F3: type, tokens and shared look
- **D2 MUST + A9:** big numbers read "2D 04H" (`big-number.js` uppercases). Show "2 d 4 h" in sentence case with an aria-label like "2 days 4 hours"; one label, "Due soon", not "Due · Due soon".
- **D5 (part):** due-soon countdowns use accent-ink. Use the notice tokens plus the word.
- **D8 SHOULD:** breadcrumbs are uppercase and underlined, and their style lives in `hood.css` but is shared. Use sentence case, 14 px Lexend, no underline, and move `.jv-crumbs` to `views.css`.
- **D9 SHOULD:** long all-caps labels ("HEAR (SPEECH TO TEXT)", "“KNOW DE WET” SCORE BY WEEK (%)", "STUDY HOURS PLANNED (h)", "THIS WEEK, IN JARVIS'S WORDS", "WHAT WILL HAPPEN", "GUESSED FROM"). Small caps only for ≤ 2-word panel titles; anything longer becomes a sentence-case h3. Fix the shared label style and your own views (Hood, Today). List any other places in your report.
- **D10 SHOULD:** inconsistent page headers. Make one `.jv-view__head` pattern (crumb → h1 → subtitle) on one left edge in `views.css`; apply it to Today and Hood; report what the other views must change.
- **D13 SHOULD:** status-line offline help text is in mono, and the mic button stays green ("on") while offline. Use `--font-ui`; the mic style follows the orb state.
- **D14 (part) SHOULD:** Controls switches use leaf green in the on state (green is reserved for growth). Use Pen Reader's pressed look (card fill, control border) in `views.css`.
- **D12 (part) SHOULD:** Today's empty state (today-free) puts a dashed box inside a card. Use a plain card with one action.
- **A10 NICE:** body line height 15/22 = 1.47 is under the 1.5 rule. Use 15/23, and give reading blocks `max-width: var(--measure)`; add a `--measure` token if missing.
- **Mono rule:** check every use of the mono font token; only tiny telemetry may use it. Report uses outside your files.
- **W-NICE:** mixed time formats ("Tue 10:00" vs "4:00 pm"). Pick "Tue 10:00 am" style in your views and report others.

## F4: Life Map, branch pages, Memory, Unsorted, facts
- **D3 MUST:** Life Map node names and the "Also in School: …" footer use JetBrains Mono; glyphs are meaningless two-letter initials. Names in Lexend 500 13 px; replace the initials with per-branch line icons (or just the leaf).
- **D11 SHOULD:** the map doesn't read as a plant. Use curved stems growing from a pot/soil base (reuse the plant component), make the leaf itself the node with the label beside it, drop or give meaning to stray dots, and give the centre an earth/green treatment instead of the orb's terracotta. Due rings and badges use the notice tokens, not terracotta (D5).
- **W5 SHOULD:** "waiting for your yes" dots come from the fixture's `pending: 1`. Work them out from `state.approvals` by branch and its ancestors (the store has approvals; ap-week's branch is fall-2026).
- **D6 (part) SHOULD:**
  - The branch card shows too much: Due + 3× Next + loops + 2 facts + More + button. Show Due + Next + one fact + Open.
  - Memory: 6 fact cards × 4 buttons. Show the actions on hover/focus or behind one "…" menu, keeping Confirm on guesses.
  - Life "Inside" chips repeat the map nodes. Hide them while the map is visible.
- **A5 (part):** Memory filters use `role=tab` + `aria-pressed` with no tabpanel. Make them plain toggle buttons like Activity's.
- **A9 (part):** every Memory article is named "Fact". Use `aria-labelledby` on the statement, and give buttons names like "Edit: <fact>".
- **A6 (part):** map labels shrink with the SVG at zoom (4 px at 200%). Give them a minimum size tied to font size, or switch to List automatically when narrow.
- **A11 NICE:** map badges ("2d", "1") are 11 px. Make them ≥ 12 px.
- **A13 NICE:** the map label says "You is in the centre". After Enter on a node, focus goes to main, so Backspace can't go back up; keep focus in the map.
- **D10 (part):** Life uses a "LIFE" label instead of an h1, and Memory/Unsorted have the subtitle on the crumb line. Use the shared `.jv-view__head` pattern (F3 adds it; until then use the class name and markup crumb → h1 → subtitle).
- **D16 NICE:** branch-proposed repeats its summary and has no full stop.
- **D18 NICE:** the filter label says "Life Tree" but the view is called "Life Map".

## F5: Activity, approvals, receipts, toasts, announcements, strip
- **A1 MUST (part):** after keyboard "Yes, do it" or Undo in Activity, or when a focused toast expires, focus drops to `<body>`. Move focus to the receipt that replaces the card, or the next card or row, or the h1.
- **W7 SHOULD (UI half):** a double-click on "Yes, do it" shows an error toast. Disable the buttons on the first click.
- **W8 SHOULD:** Yes gives no feedback on screen. Show a success toast "Booked · Undo (24 h)" with an undo action.
- **W9 SHOULD:** "Change it" is a dead end and the proposal vanishes. Open an inline tweak field and keep the item visible as "Changing…". Log declines as a quiet Activity row.
- **W10 SHOULD:** undo labels never count down ("Undo · 24 h" on everything). Show the time left, e.g. "Undo · until 9:12 am tomorrow".
- **A7 SHOULD:** toasts leave on a timer even when hovered or focused. Pause the timer on hover/focus, and return focus when a toast is dismissed.
- **A8 SHOULD:** announcements cut each other off ("Showing PPS 7." replaced by the caption ~95 ms later). Queue or merge messages in a11y.js. The strip announces "Showing X" for windows it never shows; suppress that in strip mode.
- **D12 (part) SHOULD:**
  - Empty states use the same dashed box nested in a card. Use a plain card with one action ("Connect Canvas" / "Tell Jarvis about a course").
  - activity-empty still shows the 7 filter chips. Hide the filters when the list is empty.
- **D14 (part) SHOULD:** the Activity waiting card fills a third of the width, leaving two-thirds empty. Widen it.
- **D15 NICE:**
  - The strip waiting state says "Waiting for your yes  1 waiting for your yes".
  - The strip says "Ready" while the status line says "Listening". Pick one word.
- **W-NICE:** up to 3 toasts plus the caption stack over content. Cap at 2 and place them clear of windows.

## F6: shell, navigation, controls, command bar, phone, ARIA helper
- **A2 MUST:** `html` in `ui/core/dom.js` turns `false` into `""`, so `aria-expanded=""`, `aria-pressed=""` and `aria-checked=""` all render invalid. Fix it centrally so boolean values in `aria-*` attributes render "true"/"false" with no call-site changes. Add a test.
- **A3 MUST:** in ambient mode the tabs and search are dimmed to 0.75 opacity (shell.css), which fails contrast (Daylight 2.98:1). Dim with token colours that pass, and go back to full opacity on `:focus-within`/`:hover`.
- **A4 SHOULD:** selected tabs and segmented controls differ only by a 1.22:1 fill. Add a 1 px `--control` or accent outline, or a check or underline, to the selected item (tabs, controls segments, Map/List toggle if it lives in shared code; otherwise report it).
- **A5 (part) SHOULD:** radio groups (theme, motion, chattiness) have no arrow keys and every radio is a Tab stop. Use roving tabindex with arrow keys.
- **A6 (part) + W11 SHOULD:**
  - Switch to the compact/phone layout below about 720 px. The size is set once at boot; listen for `matchMedia` changes so resizing works.
  - Fix the 6 px sideways overflow at 320 px.
- **W14 SHOULD:** a command-bar search for a setting lands at the top of Controls. Deep-link to the row and focus it.
- **A8 (part):** announce the command-bar result count ("N results") politely.
- **D4 MUST:** on phone the floating corner orb covers text and chips. Put the orb in the bottom tab bar on phone, or reserve a gutter.
- **D6 (part):** Controls › Data sources shows 6 rows. Show the top 4 and put the rest behind "More".
- **A12 NICE:** the ambient page dots are a second landmark also named "Views". Rename them "Pages".
- **A13 NICE (part):** on phone the tabs come first in reading order but sit at the bottom. Put the reading order main → tabs, or make the order match the screen.
