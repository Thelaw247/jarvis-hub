# Stage (N9)

Jarvis's screen (HUD v2 §6.5), like Huw's dedicated monitor: the windows Jarvis pulls up while he talks, in a window of their own, so the hub's home page stays calm.

- **`stage.js`**: the `/stage` view. Active: the window canvas as Huw's board (the aligned glass cluster, HUD v3 §14.2), the orb docked bottom-right (the shell's dock, 120 px; 64 px on a laptop), the shell's band (status line, the shared bottom row, the caption above it), and only three small, quiet mono words top-right, over the board (which keeps clear of them, `data-keep-clear`): **Hub** (`focusHub()`), **TIDY** (back to the order they came, `order`, and the board laid out afresh) and **CLEAR VIEW** (`close_all`: everything docks into the Rail). Standby, when the last window is put away: the orb (standby) over the big clock, fading in; windows arriving from standby bring the dock beat (the big orb slides into the corner). The Stage keeps the windows' 60 s lifetime clock (the screen that shows them owns it). Sets `data-window="stage"` (no header or tabs) and `data-stage="active|standby"` on the root.
- **`canvas.js`**: the window canvas, moved here from the Now view. On the Stage (`collage: true`) it is a board, not a grid: `layoutBoard()` gives each window its width for its kind (`panelWidth`), its kind on the board (`roleOf`: media, a big number or text; attributes `media`, `sheer`, `opens` on the window), lets it take the height its content needs (compact first when even the whole room is too short), and places them with `core/windows.js collage()` in the room above the caption's line, clear of the docked orb and the words top-right (`room()`); the window Jarvis means is placed first and drawn on top (`--z`; `active` and focus come to the front), the rest keep their spots when another arrives (`spots`, cleared by `tidy()`), and a panel more than half hidden makes the oldest that may step aside dock into the Rail. On the hub ("On the hub") and the phone it stays the grid: `WindowCanvas` (placing, stepping aside and docking, the window Jarvis means, wants-you brackets, "since you looked" notches, the voice's focus cue, recall growing out of the Rail slot, keeping focus when a window leaves) and `slideOrbToDock()`. Used by the Stage and, with "On the hub", by Now (with the now card as a panel). `canvas.css` holds the grid. Nothing is cut silently: each window fills its grid area, rows leave 28 px for the metadata under each frame, and `fit()` measures what every window holds: one that doesn't fit goes compact, then the oldest unpinned window that isn't the one Jarvis means or a question steps aside into the Rail; if nothing can, the window shows "More". Window bodies never scroll on the Stage. Esc with focus in a window closes it (it docks); toasts sit bottom-left above the status line. With windows up the hidden centre orb is `data-offstage` (nothing runs).
- **`desktop.js`**: the only place the two windows talk. `showStage()` (the "Stage · N" chip), `focusHub(path?)`, `stageReport()` / `startStageSync()` (the hub window tells `app.py` what decides the Stage), `windowsHere()` (whether pushed windows show on this screen), `stageSetting()`. Desktop: through pywebview's JS API from `app.py`; browser: named windows `jarvis-stage` and `jarvis-hub`.

The Stage window is this same page at `/?window=stage#/stage`: `core/main.js` pins its router to `/stage` (links open in the hub, the hub's `nav.go` isn't followed) and gives it no ambient screen. `app.py` makes it hidden and borderless at start on the chosen monitor (`--stage-screen N`, `JARVIS_STAGE_SCREEN`; default the primary) and `should_show_stage(state, settings, device)` decides: never with `settings.stage = "hub"`, never in game mode, shown while windows are up, and when empty Laptop B keeps it on standby while Laptop A (`--device A`, the default with `--strip`) hides it.

Scenes: `stage-active`, `stage-waiting`, `stage-crowded`, `stage-board` (five of every kind), `stage-empty` (standby), `stage-focus`. Add `&theme=day` or `&size=laptop`. Tests: `tests/e2e/test_stage.py`, `tests/e2e/test_stage_fit.py` (the collage fits: nothing off-screen, under the orb or the bottom row, no kicker covered, the window Jarvis means whole), `tests/e2e/test_glass.py`, `tests/test_stage.py`.

Clean windows (v0.4.1, HUD v2 §14.2): every window on a canvas follows one anatomy (kicker row, one hero, at most one line, one footer item; the rest in its "Why?" drawer), and `core/windows.js` `cluster()` packs them as one aligned cluster: width tiers S/M/L by content, a 16 px gutter, masonry columns on one top baseline, media large in the centre column, centred left of the docked orb, overlapping only when crowded. The hub's own canvas ("On the hub") uses the same packer whenever windows are up.

One window (v0.17.0, N10): "On the hub" is now the default for `settings.stage` (also when unset), so one Jarvis window opens and its orb docks to the corner when windows come up. Every window on a board can be arranged by hand in `canvas.js` (`press`, `gripKey`, `hold`, `letGo`): drag its glass to move it, drag the corner grip to size it; on the grip the arrows size, Shift+arrows move and Home (or a double-click) gives it back to Jarvis's layout. A hand-placed window is exempt from the 60 s lifetime (`WindowClock.keep`), is solid (never dimmed), stacks by last touched, and "Tidy" lets them all go. Pulling a window out (its "own window" tool button, or a drag past the edge) puts its id in `core/popped.js` (`localStorage["jv-popped"]`, shared by both windows): the hub stops drawing it and the second window, now the holder (`data-stage="holder"`: no orb, no voice, no bottom row), draws only those. `app.py` shows the holder (an ordinary framed window, "Jarvis Windows") only while `stageReport().state.popped > 0`; closing it or "Back to the hub" clears the registry. "Stage window" keeps the old full-screen second window. Scenes: `stage-holder`, `stage-holder-empty`, `stage-holder-live`, `now-pulled-out`. Tests: `tests/e2e/test_one_window.py`, `tests/test_stage.py`.
